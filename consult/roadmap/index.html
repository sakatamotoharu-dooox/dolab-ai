ロードマップ

運営チームが設計したAI推進の進め方です。3つのフェーズに分かれており、一緒に進めていきます。

全体の流れ
Phase 1 ● 進行中
現状把握
今の業務を見える化して、どこをAIで変えるかを決める
Phase 2 ○ 未着手
AI導入・テスト
設計書・AIパックを使って実際に動かしてみる
Phase 3 ○ 未着手
本番稼働・自走化
現場に定着させて、自分たちで改善できる状態をつくる
Phase 1 — 現状把握フェーズの進め方

まずは「今どんな業務をどうやっているか」を整理します。ここをしっかりやっておくと、どこにAIを使うと一番効果が出るかがはっきり見えてきます。

1

業務フローを見える化する

今やっている業務の流れを図や表に書き出します。頭の中にあるものを「見える形」にすることで、問題のある場所や自動化できる場所が見つかります。

細分化するときの3つのポイント

① フロー（作業の流れ）

一つひとつの作業を、順番どおりに細かく書き出します。

特に明確にすること
  • どこで「Aならこっち / Bならあっち」と分かれるか（分岐点）
  • どこで人が「判断」しているか
  • どこで「待ち時間」が発生しているか
  • どこで「確認」や「承認」が必要か
例： 見積依頼を受けた → 担当者が確認 →「新規か既存か」で分岐 → 新規なら上長に報告 → 既存なら自分で作成
② 行（縦の切り口）

同じ「業務名」でも、条件によってやり方が違うことがあります。それを行（縦）で分けます。

分け方の例
  • 新規のお客様 / 既存のお客様
  • 担当者の役割（営業 / 事務 / 管理職）
  • 連絡手段（メール / 電話 / FAX）
  • 金額の大小（少額 / 高額）
  • 案件の種類（通常 / 急ぎ / クレーム）
例： 「請求書作成」という業務でも、新規と既存では確認先も書類も違う → 行を分けて整理
③ 列（横の切り口）

業務の大きなカテゴリを横に並べます。全体の流れを俯瞰できるようにします。

並べ方の例（業種別）
  • 建設業：問い合わせ → 見積 → 契約 → 施工管理 → 検査 → 請求
  • 社労士：相談受付 → 書類収集 → 手続き申請 → 確認 → 報告
  • 製造業：受注 → 生産計画 → 製造 → 検品 → 出荷 → 請求
  • 小売・EC：注文受付 → 在庫確認 → 発送 → フォロー → 返品対応
2

現場で確認して、実態に合わせる

最初に作る業務フローはあくまで「たたき台」です。現場の担当者や実際のデータと照らし合わせて、正確な内容に仕上げていきます。これまで「なんとなくやっていた」ことを言葉にする作業でもあります。

確認するときの3つの視点

🖥 システム・ツールの流れ

どのソフトやアプリを使って作業しているか。情報がどのシステムから次のシステムへ動いているか。

📄 書類・データの流れ

どんな書類やファイルが発生するか。誰が作って誰が受け取るか。どこに保存されているか。

🗣 人の判断・やりとり

誰が誰に何を伝えるか。どこで承認が必要か。「口頭で確認している」ような暗黙のルールはないか。

すり合わせで確認する項目の例

担当者情報
誰がその業務を担当しているか・役職・兼任しているか
発生頻度・タイミング
毎日 / 週1回 / 案件ごと / 月末にまとめて など
使っているツール・システム
Excel / メール / kintone / LINE / 専用ソフト など
かかっている時間
1件あたりの作業時間・繁忙期はどれくらい増えるか
判断の基準
どういう場合に誰が決めるか・どこまで自分で判断していいか
発生する書類・データ
見積書 / 注文書 / 請求書 / 日報 / 議事録 / 報告メール など
よくある手戻り・ミス
どこで間違いが起きやすいか・何度も確認が必要なのはどこか
属人化している部分
「この人しかわからない」作業・マニュアル化されていない暗黙のやり方
確認先・連絡先
社内の上長 / 他部署 / 取引先 / 外注先 など、誰に何を確認するか
繁忙期・例外ケース
月末 / 決算期 / 季節変動 / イレギュラーな対応が発生するパターン
3

目的を決めて、チームで共通認識をつくる

業務フローを作る前に「なぜ作るのか」を明確にします。目的によって、何を細かく調べるか・誰に何を聞くかが変わります。目的をチーム全員で共有してから進めると、ズレなく正確な業務フローが作れます。

目的 → 切り口の例

目的：「メール対応にかかっている時間を減らしたい」

この目的なら、こういう切り口で情報を集めます：

  • 誰が対応しているか（担当者 / 社長 / チーム全員）
  • どんなメールが来るか（問い合わせ / 発注 / クレーム / 社内連絡）
  • 1日何件くらい来るか・繁忙期はどのくらい増えるか
  • 返信にどのくらい時間がかかっているか（文章を考える時間 / 情報を調べる時間）
  • どこが一番大変か（毎回同じことを書いている / 確認が必要で返信できない）
目的：「新人でも同じクオリティで見積書を作れるようにしたい」

この目的なら、こういう切り口で情報を集めます：

  • 熟練者はどんな手順で見積書を作っているか
  • どこで経験・勘が必要になるか（単価の判断 / 工数の見積もり）
  • 過去の見積書のうちどのパターンが多いか（定型 / 特注 / 修正依頼）
  • ミスが起きやすいのはどの項目か
  • 承認フローは誰がどこで確認しているか
目的：「月末の請求・経理作業の手間をなくしたい」

この目的なら、こういう切り口で情報を集めます：

  • 月末に何の作業がどの順番で発生するか
  • データはどこからどこへ転記しているか（システム → Excel → 会計ソフト など）
  • 手打ちで入力している作業は何件・何分かかるか
  • ミスが起きたときはどこまで戻って修正するか
  • 取引先ごとにフォーマットや条件が違うケースはあるか

チームで共通認識をつくるコツ

目的から出てきた「切り口」をまず言葉にして、社長・担当者・運営チームで確認します。「今回は○○という目的で、△△と□□を重点的に整理します」と一言共有するだけで、ヒアリング時のズレがなくなり、業務フローの精度が上がります。
